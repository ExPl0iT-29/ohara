# Proposal

## Why

The Android app is built through Expo tooling: `/android` is regenerated by `expo prebuild` on every build, and the release path planned in `public-release-readiness` uses EAS Build, a hosted Expo service. The owner wants development and releases not to depend on Expo's build tooling or services: one committed native project, built with standard Gradle commands on any machine with the Android SDK.

## What Changes

- Commit `mobile/android/` as the source of truth for the native project (generated once from the current config with `com.ember.ohara`, `versionCode` 1 and blocked storage/overlay permissions).
- Build exclusively with the Gradle wrapper: `./gradlew installDebug`, `assembleRelease`, `bundleRelease`.
- **BREAKING (workflow):** stop using `expo prebuild` and `expo run:android`; `android/` must not be regenerated, because manual native edits would be lost. Native settings (application ID, version, permissions, signing) are now edited in `android/`, not `app.json`.
- Remove `mobile/eas.json`; there is no EAS dependency.
- Release signing reads the Play upload key from user-level Gradle properties or environment variables; nothing secret is committed. Without a key, release builds fall back to debug signing with a loud warning.
- `package.json` scripts call Gradle directly.
- Expo **libraries** (router, SQLite, share intent, file system and so on) stay as ordinary npm dependencies. Gradle compiles them through autolinking, and the release task embeds the JS bundle itself, so no Expo command needs to be run by hand. The Metro dev server for live JS reloading is still started with `npm start`.

**Non-goals:** replacing Expo libraries, iOS, CI setup, changing app behaviour.

## Capabilities

### New Capabilities
- `native-build`: how the Android app is built and signed from a committed native project using only Gradle.

### Modified Capabilities

None. (`public-release-readiness` is still in flight; its EAS-specific task is updated in place.)

## Impact

- **Repo:** `mobile/android/` (about 50 files, 0.5 MB) now tracked; `mobile/.gitignore` no longer ignores it; `mobile/eas.json` removed.
- **Docs:** README run and release sections, `mobile/android/SIGNING.md`.
- **In-flight change:** `public-release-readiness` design D3 and task 1.2 move from EAS to Gradle.
- **Dev machines:** need JDK 17+ and the Android SDK (as any native Android project does).
